# Голос бренда / AISOV — Research UI Kit v2.3.3

UI-kit — единая дизайн-система для публичных GEO/AI-исследований «Голоса бренда». Исследование рассматривается не как презентация, а как **адаптивная веб-страница**, которая должна одинаково хорошо работать на десктопе и смартфоне.

## Что входит

- `index.html` — интерактивная витрина UI-kit.
- `research-page-template.html` — стартовый HTML-шаблон нового исследования.
- `ui-kit.css` — компоненты, responsive-правила и визуализации.
- `aisov-icons.css` — CSS mask-image система универсальных иконок.
- `research-runtime.js` — адаптивные data-labels для таблиц и mobile handoff.
- `design-tokens.json` — цвета, типографика, сетка, радиусы и responsive tokens.
- `assets/ai/` — SVG-иконки AI-моделей и AI-выдачи.
- `logo-mark.png` — марка «Голоса бренда».

## Неприкосновенная визуальная база

Основные стили и цвета сохраняются между исследованиями. Фокус-бренд, CTA и активные состояния используют `#1B3FAA`; светлый аналитический режим остаётся основным, тёмный режим используется как крупный акцент.

UI-kit не должен превращаться в новый дизайн под каждый рынок. Меняются данные, CJM, предметный визуал и композиция конкретных блоков, но не базовая визуальная система.

## Типографика и читаемость

Абсолютный минимум для **любого видимого текста — 12 CSS px** в итоговом DOM: включая подписи графиков, осей и SVG, таблицы, легенды, бейджи, сноски, состояния, псевдоэлементы с текстом и мобильные варианты. Иконки и декоративные фигуры текстом не считаются. Размер проверяется через `getComputedStyle`, а у масштабируемого SVG — ещё и по фактическому отображению: `font-size="12"` внутри `viewBox` не гарантирует 12 px на экране.

Основная шкала: 16 px / 24 px — текст и методология; 14 px / 20 px — вторичные пояснения; 12 px / 16 px — только короткие подписи и плотные данные. Лид и заголовки крупнее по контексту. На телефоне основной текст сохраняет 16 px, а поля ввода и выбора — не меньше 16 px. **12 px — нижняя граница, а не целевой размер всего интерфейса.** Отдельные элементы можно уменьшать ради композиции, но не ниже этой границы.

При увеличении текста компонент должен перестраиваться: высота строки и карточки растёт по содержимому, длинные названия и URL переносятся, а значимые слова и числа не прячутся в `ellipsis` или под `overflow:hidden`. Для широких таблиц допустим горизонтальный скролл **внутри таблицы**, но не всей страницы; альтернатива — карточная раскладка. Если SVG-график на узком экране уменьшает реальные подписи ниже 12 px, используйте локальный скролл графика или табличное представление тех же данных. Цвет текста и фона проверяется на читаемый контраст; уменьшать контраст вместе с размером подписи нельзя.

Приёмка: проверить вычисленный размер и отсутствие обрезания на 320, 360, 375, 390, 414, 430, 768, 1023, 1024 и 1440 px; раскрыть списки, пройти состояния переключателей и фильтров; отдельно просмотреть SVG после масштабирования. Проверять в Chromium и WebKit. Ни одно текстовое поле не должно вызывать горизонтальный скролл страницы.

## Исследование как веб-страница

В каждом исследовании обязательно:

1. `<meta name="viewport" content="width=device-width,initial-scale=1">`.
2. Один и тот же URL и контент для desktop/mobile.
3. Layout перестраивается по ширине viewport; не используется отдельная «мобильная версия» сайта.
4. Не отключается масштабирование браузера.
5. На смартфоне не должно быть горизонтального скролла **страницы**.
6. Интерактивные элементы должны быть удобны для touch.
7. Fixed/sticky элементы не должны перекрывать контент и должны учитывать safe area.

### Breakpoints

| Диапазон | Режим | Поведение |
| --- | --- | --- |
| `≤ 390px` | small phone | 1 колонка почти для всех блоков |
| `391–767px` | phone | mobile-first layout |
| `768–1023px` | tablet | 1–2 колонки |
| `≥ 1024px` | desktop | полный аналитический layout |
| `≥ 1440px` | wide | контейнер остаётся ограниченным `--wide` |

## Приоритет контента на смартфоне

Порядок чтения важнее сохранения desktop-композиции. На мобильном пользователь сначала должен получить:

**тезис → ключевые KPI → основной график → CJM/сравнения → детали → источники**.

Декоративный `hero-art` на смартфоне скрывается. Данные при этом не удаляются.

## Таблицы на мобильном

На desktop таблица остаётся обычной таблицей. На `≤ 767px` каждая строка превращается в карточку:

`Название сущности`

`Видимость → 34,2%`  
`SOV → 18,6%`  
`Позиция → 2,3`

`research-runtime.js` автоматически берёт подписи из `<thead>` и добавляет их в `data-label` для мобильной карточной раскладки.

Не дублировать две версии одной таблицы в DOM.

## Heatmap на мобильном

Desktop heatmap остаётся матрицей. На смартфоне строка матрицы превращается в вертикальную карточку, а каждая ячейка отображается как:

`ChatGPT → 58%`  
`Gemini → 81%`  
`DeepSeek → 86%`

Цвет интенсивности сохраняется, но точное значение и название модели всегда остаются текстом.

## CJM на мобильном

CJM остаётся фирменным каркасом исследования.

- Overview: 2 колонки на обычном телефоне, 1 колонка на очень узком.
- CJM Layers: этапы идут вертикально без горизонтального свайпа.
- CJM Benchmark: внутри этапа сначала название, затем два бара, затем лидер и разрыв.
- Prompt Coverage: сохраняет компактный горизонтальный bar внутри ширины экрана.

Порядок этапов CJM нельзя менять только ради адаптива.

## Compact mobile handoff

На смартфоне автоматически появляется неблокирующая плашка:

**Сохраните исследование**  
Скопируйте ссылку, чтобы сохранить исследование и открыть его позже.

В самой плашке не дублируется название бренда/сервиса: контекст уже понятен из страницы, поэтому верхняя строка «Голос бренда» убрана ради компактности.

Действия:

- `Копировать ссылку` — копирует публичный canonical URL исследования (если его нет — текущий адрес), затем показывает подтверждение; при ошибке — инструкцию скопировать адрес из браузера.
- `×` — закрывает плашку на текущую сессию.

### Почему плашка компактная

Это не modal и не bottom sheet на половину экрана. Пользователь может продолжать читать исследование сразу. Компонент не имеет backdrop и резервирует под себя место внизу страницы, чтобы не перекрывать контент.

### Техническое подключение

Добавить к `body`:

```html
<body data-mobile-handoff="true">
```

Добавить markup компонента из `research-page-template.html`, затем:

```html
<script src="research-runtime.js"></script>
```

Плашка показывается только на `≤ 767px`. После закрытия используется `sessionStorage`, поэтому в пределах текущей сессии она не появляется снова на том же URL.

## Touch и accessibility

- визуально маленькая кнопка закрытия имеет hit-area `44×44px`;
- основные кнопки на mobile — минимум `44px` по высоте;
- действия не зависят от hover;
- у icon-only controls есть `aria-label`;
- копирование сообщает результат через `role="status"`;
- fixed-плашка учитывает `env(safe-area-inset-bottom)`;
- `prefers-reduced-motion` отключает необязательные transitions;
- keyboard focus остаётся видимым.

## Графики

Desktop и mobile используют один набор данных.

### Line chart

Используется для временных рядов. На мобильном:

- SVG остаётся fluid;
- точки не выходят за plot area;
- легенда переносится;
- подписи не должны требовать горизонтального скролла.

### Horizontal bars

Предпочтительны для рейтингов брендов, доменов и источников. На мобильном уменьшается ширина колонки с названием, а bar получает оставшееся место.

### CJM benchmark

На каждом этапе обязательно показать:

- фокус-бренд;
- значение фокус-бренда;
- лидера этапа;
- значение лидера;
- разрыв в п.п.

Если фокус-бренд сам лидер, вместо отрицательного gap выводится статус `Лидер этапа`.

## Фильтры

На desktop поля могут стоять в строку. На mobile они переходят в одну колонку. Поля ввода используют размер шрифта не меньше 16px, чтобы мобильный браузер не масштабировал страницу при focus.

## Иконки

Generic-иконки используются через `aisov-icons.css` и наследуют `currentColor`.

```html
<span class="a-icon a-icon--route a-icon--brand"></span>
```

Размеры: `sm 16`, `md 24`, `lg 32`, `xl 48`.

Логотипы AI-платформ не перекрашиваются через mask — используются оригинальные SVG из `assets/ai/`.

Нейминг:
- ChatGPT
- DeepSeek
- Gemini
- GigaChat
- Perplexity
- Alice AI / YandexGPT
- Google AI Overview
- Alice AI на поиске

## Как начать новое исследование

1. Скопировать `research-page-template.html`.
2. Заменить title, hero, KPI и данные.
3. Определить CJM категории.
4. Собрать data blocks из UI-kit.
5. Проверить desktop `1440 / 1280 / 1024` и tablet `1023 / 768`.
6. Проверить mobile `430 / 414 / 390 / 375 / 360 / 320`.
7. Проверить минимум 12 CSS px для всех видимых текстов и фактический размер SVG-подписей; у основного текста на телефоне сохранить 16 px.
8. Убедиться, что нет обрезания важных подписей и горизонтального скролла страницы.
9. Проверить таблицы, heatmap и CJM в mobile-card режиме, а также все состояния фильтров и раскрытий.
10. Проверить копирование canonical URL, резервный сценарий, сообщение об ошибке, закрытие плашки, keyboard focus и `prefers-reduced-motion`.
